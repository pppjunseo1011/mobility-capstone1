# SCOUT 압축 해제 운영 안내

`scripts/extract-scout.py`는 약 **371.02GB의 원본 압축 파일을 보존**하고 새 작업 폴더에 순차 추출한다. 전체 압축 파일의 SHA-256 재대조와 필수 디렉터리 확인을 마친 뒤에만 최종 폴더 이름으로 변경한다. 실제 시작·완료 시각과 진행 상태는 아래 상태 파일을 기준으로 확인한다.

**2026-10-27 14:31:10 KST 완료:** 12:07:03부터 8,647초 동안 파일 1,124,853개, 374,109,919,942바이트를 추출했다. 최종 루트는 `datasets/scout/extracted/scout`이며 압축 파일 SHA-256이 다운로드 검증 기록과 일치했다. 이후 수행한 [실제 표본 어댑터 검증](scout-real-validation.md)은 이 추출 결과와 별도 검증이다.

| 경로 — 프로젝트 루트 기준 | 용도 |
|---|---|
| `datasets/scout/archives/scout.tar.gz` | 보존하는 원본 압축 파일 |
| `datasets/scout/.extracting-scout/` | 진행 중 또는 실패한 추출 작업 폴더. 내부에 `scout/` 생성 |
| `datasets/scout/extracted/scout/` | 추출 완료 후 사용할 SCOUT 데이터 루트 |
| `datasets/scout/scout-extract.status.json` | 상태, PID, 시각, 처리량, 공간 및 오류 기록 |
| `logs/scout-extract.log` | 백그라운드 실행 로그 |

## 실행과 상태 확인

```bash
cd /media/aimlab/HDD00/users/junseo-capstone/scout-mtmc

# 새 추출 작업 시작: 최종 폴더와 작업 폴더가 모두 없어야 한다.
python3 scripts/extract-scout.py start

# 마지막 기록된 상태 확인
python3 scripts/extract-scout.py status

# 최근 로그 확인
tail -n 50 logs/scout-extract.log
```

`start`는 별도 세션의 백그라운드 프로세스를 실행하고 초기 실행 상태를 확인한다. 시작 명령이 성공했다는 것은 추출 완료를 뜻하지 않는다. VS Code나 터미널을 닫아도 계속 실행되지만, 서버 재부팅 후 자동으로 다시 시작하는 서비스는 아니다. 상태 파일도 마지막 기록이므로 비정상 종료·재부팅 뒤에는 기록만으로 프로세스가 살아 있다고 판단하지 않는다.

`state=complete`는 추출·해시 대조·필수 디렉터리 검사·최종 이름 변경이 끝났다는 뜻이다. 전체 이미지 디코딩, 주석 품질 검증 또는 모델 추론 성공을 뜻하지 않는다.

## 진행률과 검증 범위

- `compressed_progress_percent`는 읽은 **압축 바이트** 비율이다. 추출된 파일 수나 최종 데이터 검증의 완료 비율이 아니다. `eta_seconds`도 평균 압축 읽기 속도에 따른 추정치이며, 파일 구성과 디스크 부하에 따라 달라진다.
- 다운로드 상태의 완료·gzip 검증 통과 여부, SHA-256 기록 간 일치, 압축 파일 크기를 먼저 확인한다. 추출 중 읽은 압축 데이터와 tar 종료 뒤의 남은 압축 바이트까지 모두 해시에 포함한다.
- 최종 SHA-256이 기존 검증값과 같아야 완료 처리한다. 이는 **이전에 gzip 무결성 검증을 통과한 파일과의 동일성 확인**이며, 이번 추출에서 gzip CRC를 별도로 재검사했다는 뜻은 아니다.
- tar 내부의 경로 탈출, 링크, 특수 파일과 sparse 파일은 거절한다. 파일 내용 길이와 추출 도중 원본 압축 파일의 변경 여부도 확인한다.

## 자원 사용과 기존 작업 보존

각 파일을 쓰기 전에 파일 크기와 **50GiB 여유 공간**을 함께 확보할 수 있는지 검사하고, 추출 중에도 남은 공간을 확인한다. 다른 작업의 동시 디스크 사용까지 통제하는 예약 공간은 아니다. 공간이 부족하면 실패 상태와 부분 결과를 남긴다.

프로세스에는 niceness 10을 적용하며, `ionice`가 설치되어 있으면 class 2 / priority 7을 적용한다. 낮은 우선순위로 실행하더라도 압축 읽기와 이미지 파일 생성에는 디스크 I/O가 발생한다.

기존 최종 폴더나 작업 폴더를 덮어쓰지 않으며, lock으로 중복 추출을 막는다. 실패·중단된 부분 결과는 `.extracting-scout/`에 보존한다. **자동 재개는 지원하지 않는다.** 부분 폴더가 남아 있으면 `start`를 다시 실행해도 재사용하지 않으므로, 원인과 보존 필요성을 확인한 뒤 별도로 처리해야 한다.

이 스크립트는 원본 압축 파일과 모델 코드를 수정하지 않고, 다운로드·가중치 설치·어댑터 실행·추론·학습을 자동으로 시작하지 않는다.
