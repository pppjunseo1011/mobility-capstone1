# UWIPL V4 검출 진단 및 단일 조건 실험 (2026-11-08)

현재 TITAN RTX 서버에서 D1~D3와 다수결·STCRA 후처리 비교를 완료했다. 개발/별도 구간 각각 5초·30초, 9조건으로 추적 지표 36행과 검출 진단 1,440행을 작성했다. D4 미세조정은 학습 준비 및 데이터 로더 검증까지만 완료했으며 학습하지 않았다.

ZIP은 결과 검토용이다. 모델 가중치, 전체 데이터셋, 임베딩 캐시와 실행 환경은 포함하지 않는다. 코드의 과거 실험 의존 자료는 원래 프로젝트에 있으므로 ZIP만으로 전체 추론을 재실행할 수는 없다.

## 고정 조건과 실험

V3 기준: 앵커 넓이 >1,000px², 거리80, 점수>0.95, 11시점, 다수결15개 관측, 10 FPS, STCRA OFF. BoT-SORT new=0.7/high=0.4 유지. 인원 수 제한은 없다. 원본 V3 기준 지표와 정확히 일치하는지 확인했다.

D1은 높이×너비 800×1440, 1088×1920, 1280×2304다. D2는 원본 1920×1080을 1152×648 타일 4개로 나누고 전체 영상 크기의 20%를 겹쳤다. 타일마다 800×1440 추론 후 원본 좌표에서 NMS 0.7로 합쳤다. 전체 영상 추가 패스는 없다. D3은 기본 해상도에서 NMS만 0.8로 변경했다. 새 검출마다 OSNet 5종 특징과 추적을 다시 계산했다.

추가 실험은 기본 검출에서 다수결20/30을 각각 비교했다. STCRA는 기존 4/3/2 제어 결과와 그 뒤 다수결15를 적용한 결과를 비교했다. smooth_avg_tracks는 실행하지 않았다. 해상도와 다수결을 함께 바꾼 조합 실험도 하지 않았다.

검출 조건 중 개발 5초·30초 평균 HOTA는 1088×1920이 45.26으로 가장 높았다(기준44.84). 평균 검출 F1은 1280×2304가 가장 높았다. 후보는 개발 결과로 골랐으며 별도 구간 점수로 다시 선택하지 않았다.

개발 30초의 검출 재현율/정밀도는 기준53.08/75.57에서 1088×1920의56.23/73.68, 1280×2304의55.97/76.50으로 바뀌었다. 타일링은 재현율56.22를 얻었지만 정밀도61.59로 낮아졌다. 별도 30초에서는 타일링으로 TP가854개 늘어난 반면 평가상 FP가7,033개 늘었다. 그중 이미 대응한 GT와 겹치는 미배정 검출 증가분은513개여서 단순 타일 중복만으로 설명되지 않는다.

기준 검출의 높이50px 미만 GT 재현율은 개발30초37.51%, 별도30초25.25%다. 작은 사람의 누락이 크지만, 일부 GT 투영 박스가 영상과 어긋나 보이므로 모든 누락을 검출기 문제라고 단정하지 않는다.

## 평가와 해석상 제한

- sequence_1/cam_0~7. 개발 원본 frame277~326/277~576. 개발30초는 기존 카메라 timestamp 차이가 최대2.051초다.
- 별도 구간은 카메라별 약2807~3106, 2,389/2,400 슬롯을 timestamp 정렬했고 최대차42ms다. 11개 빈 슬롯은 평가에서 제외했다. V3에서도 사용한 구간으로 신규 블라인드 테스트는 아니다.
- 5초는 각30초 안에 포함된다. 두 점수 평균은 독립 표본의 통계 검정이 아니다.
- HOTA·DetA·AssA는 카메라별 2D 평가의 결합값, IDF1 view는 공유 Global ID 관측 규약이다. 공식 SCOUT 벤치마크 최종 점수라고 주장하지 않는다.
- 검출 진단은 IoU≥0.5 유효 대응 수를 먼저 최대화했다. V3의 ungated assignment보다 기준 TP가 개발5초1개/30초14개 늘었으며 모든 V4 검출 조건에 같은 방식으로 재계산했다. 이는 모델 향상이 아니다. 추적 평가 구현과 V3 기준 추적 지표는 변경하지 않았다.
- 확인한 표본의 MOT와 raw projections_2d 좌표가 정확히 일치하고 입력 JPEG도 원본과 일치했다. 시각적 GT 어긋남의 원인은 미확정이며 GT를 임의 이동·제외하지 않았다.
- GT 박스 진단 HOTA46.68→76.84는5초에서 박스뿐 아니라 score=1도 바꾼 결과다. 순수 재현율 효과나 보장 상한으로 해석하지 않는다.

## D4 준비와 남은 작업

평가 sequence_1과 분리한 sequence_2의22카메라로 학습18,115장·내부 검증3,526장의 COCO 주석과 원본 프레임 대응표를 준비했다. timestamp 중복을 제거하고 시간 경계에119.6초 간격을 뒀다. 주석이 없는1,670장은 빈 정답 이미지로 가정하지 않고 제외했다. 원본 YOLOX MOTDataset·TrainTransform으로22카메라×2분할44장의 로딩·전처리가 통과했다.

D4는 요청의 “D1~D3 결과 보고” 이후 단계로 남겨 두었다. 학습용 GT와 픽셀의 정합성 검토, 학습 Exp 경로·epoch·LR·seed·해상도 확정 후 학습할 수 있다. 평가 sequence_1의 지표로 checkpoint를 선택하지 않아야 한다. 원래 가중치는 변경하지 않았다.

## 실행 기록

- scripts/run-uwipl-v4.py: 이번 기존 Docker 호스트용 실행기. 개발GPU0/별도GPU1, 완료 상태 캐시 재사용. MIG의 기존 컨테이너 안에서 이 실행기를 그대로 실행하지 않는다.
- scripts/uwipl-v4-detect.py: 검출/타일링 구현. 기준8개 이미지의 박스·점수가 기존 결과와 정확히 일치했다.
- scripts/uwipl-v4.py: 진단·추적·후처리, scripts/analyze-uwipl-v4-losses.py: 단계별 손실 분석.
- scripts/report-uwipl-v4.py build: 기존 결과 재집계와 HTML 생성. package는 새 ZIP을 만들며 기존 ZIP 덮어쓰기를 거부한다.
- outputs/uwipl-v4-20261108/reproducibility.json과 logs/*.status.json에 소스·가중치 해시, 명령, 시간 기록을 보존했다.
