## 30초 주요 결과

각 셀은 개발 / 별도 값이다. HOTA·IDF1은0~100, IDSW는횟수다.

| 설정 | HOTA | IDF1 view | IDSW |
|---|---|---|---|
| 기준 다수결15 | 43.00 / 35.51 | 46.90 / 36.71 | 265 / 133 |
| 다수결30 | 43.64 / 35.73 | 47.45 / 37.12 | 140 / 75 |
| 다수결40 | 43.89 / 35.79 | 47.90 / 37.41 | 105 / 69 |
| 다수결50 | 44.28 / 35.96 | 48.01 / 37.03 | 98 / 59 |
| 다수결30 + STCRA + 후15 | 43.24 / 34.72 | 49.73 / 37.47 | 207 / 111 |
| 다수결30 + STCRA + 후30 | 43.42 / 35.02 | 49.90 / 37.36 | 141 / 89 |

다수결50은 두30초 구간에서 HOTA·IDSW를 개선했지만 별도 IDF1 view는40보다 낮다. 5초에서는30이40/50보다 HOTA가 높았다. STCRA 조합은 개발 IDF1 view를 높였지만 별도 HOTA는 기준보다 낮았다. 하나의 설정이 모든 지표·길이에서 가장 좋다는 결론은 아니다.

## 고정 조건 및 재사용

넓이>1,000px², 앵커 거리80, 점수>.95, 시점11, 검출800×1440, BoT-SORT new=.7/high=.4, 10 FPS를 유지했다. 다수결 길이는 Local tracklet의 배정된 관측 수다. 마지막 짧은 블록은 앞 블록 결정을 유지하는 기존 규칙을 사용한다.

STCRA는 기존 코드·H·포즈를 사용해 거리4/3/2와 confidence.65/.70/.75로3회 실행했다. 이후 다수결15 또는30을 적용했다. 입력 다수결15의 STCRA 출력과 다수결15/30 결과가 기존V4와 정확히 일치하는지 검증했다. GT는 모델 출력 생성에 사용하지 않았다.

## 재평가 규약

V4의9조건을 개발·별도5초/30초에서 다음3규약으로 다시 평가했다. 새 조합 실험의 재평가가 아니라 기존V4 저장 결과의 재평가다.

1. height_ge50_strict: 관측별 GT 높이≥50px만 유지, 예측은 전체 유지. 작은 사람에 대한 예측도 미대응이면 FP가 될 수 있다.
2. height_ge50_ignore: 큰 GT에 먼저 IoU≥.5로 대응하고 남은 예측 중 작은 GT에 대응한 것만 중립적으로 제외하는 보조 진단. 미대응 예측은 계속 평가한다. 제외 목록은 ignored_rows.json에 있다. 고정IoU.5 제외 규칙을 HOTA 전체 곡선에도 적용하는 프로젝트 진단 규약이다.
3. iou_0.3: 전체GT에서 Identity/CLEAR의 대응 문턱만.3으로 변경. 표준HOTA는 IoU.05~.95 평균이므로 원래 값과 같고 실제로 일치했다. 별도 HOTA_at_0_3/DetA_at_0_3/AssA_at_0_3 열은 곡선의 단일 지점이다.

높이 제한으로 평가 점수가 바뀐 것을 모델 개선으로 보고하지 않는다. 같은 baseline 개발30초 HOTA는 strict39.00/ignore55.52, 별도30초는40.10/53.74다. FP 처리와 평가 대상의 차이이므로 두 규약을 구분해야 한다.

## 타일링 보류

현재 스크립트에는 전체 영상+타일 결과 병합, cam_3/4 등 카메라별 타일 분기, tile-only 점수 기준 옵션이 없다. 검출 출처와 행 대응, 병합 NMS, 새 임베딩 연결을 추가해야 하므로 “코드 수정 없이 설정 조합” 범위에서 실행하지 않았다. 이번 결과에 타일 혼합의 가상 수치는 없다.

## 한계와 재현

개발30초의 최대 카메라 시간차2.051초, V3부터 사용한 별도 구간, 5초/30초 중첩, STCRA 단일Z=0 평면 가정은 그대로다. 새 블라인드 검증 또는 공식 SCOUT World 평가가 아니다. IDSW는 이전UWIPL과 동일한 TrackEval CLEAR를 사용했다.

원본 모델·기존 스크립트 해시는 unchanged_code.json에 보존했다. 새로 추가한 것은 실행/평가/보고서용 스크립트뿐이다.

```bash
# 기존 Docker 호스트, 프로젝트 루트, 기존 캐시가 있는 경우
python3 scripts/run-uwipl-v4-config.py
python3 scripts/report-uwipl-v4-config.py verify
python3 scripts/report-uwipl-v4-config.py build
```

MIG의 기존 컨테이너 안에서는 Docker 실행기를 중첩 실행하지 않는다. ZIP은 결과 검토용이며 데이터셋·가중치·전체 특징 캐시는 별도로 필요하다.
